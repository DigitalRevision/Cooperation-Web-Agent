# Промышленная кооперация — MVP

**Команда**: DigitalRevision
**Тема**: SM01

Цифровая система промышленной кооперации в визуальном языке портала soyuzmash.ru. Пилотный регион — Волгоградская область.

**Принцип:** реальные данные → проверенные источники → поиск → сопоставление → производственная цепочка → поставщик → заявка → кооперация.
Неизвестное хранится как `null` и показывается как «Нет открытых данных», «Не указано», «Цена по запросу» или «Требует подтверждения».

## Состав

| Каталог | Что внутри |
|---|---|
| `data/` | Git-репозиторий данных: `companies/<id>/{company,products,sources}.json`, `products/`, `okved/`, `okpd2/`, `materials/`, `technologies/`, `regions/`, `relations/`, `warehouses/`, `sources/` (реестр и журнал обхода) |
| `site/` | Фронтенд: `src/` (CSS и JS по модулям), `dist/index.html` + `dist/data.json` после сборки |
| `backend/` | FastAPI: каталог, поиск с объяснением, заявки, предложения, цепочки, замена поставщика, админ-API; `sql/schema.sql` — модель PostgreSQL; `tests/` |
| `crawler/` | Scrapy: robots.txt, rate limit, retry, логирование, дедупликация, нормализация, проверка источника, запись в `data/` и коммит |
| `sync/` | Ежедневная синхронизация с реестрами ФНС и Федресурсом: поиск новых промышленных компаний региона и соседних областей, статус и метка закрытия, риски, отчётность, коды ОКВЭД. Подробно: [docs/SYNC.md](docs/SYNC.md) |
| `tools/` | `seed_research_2026_09_24.py` — первичный сбор с источниками; `validate_data.py` — CI-проверка; `build_site.py` — сборка сайта |

## Запуск

```bash
python tools/validate_data.py          # проверка данных
python tools/build_site.py             # site/dist/
cd backend && pip install -r requirements.txt && python -m pytest -q && uvicorn app.main:app --reload
docker compose up                      # db (pgvector) + redis + api + web
docker compose --profile crawl run crawler
python -m sync                         # сверка с реестрами и поиск новых компаний (раз в сутки: --daemon)
```

Настройки сервера API:
- `PK_TOKENS` — токены доступа, JSON `{"токен": "роль"}` (роли: user, company_admin, moderator, admin). Без переменной работают только локальные `dev-user` и `dev-admin`; в `docker compose` по умолчанию токенов нет, и защищённые методы закрыты.
- `PK_TG_WEBHOOK_SECRET` — секрет вебхука бота Telegram (тот же, что в `setWebhook(secret_token=…)`). Без него вебхук отвечает 503.

### Публикация сайта на claude.ai

Сайт хранит заявки, предложения, регистрации и решения модератора в хранилище приложения (`db`). Регистрации содержат персональные данные, а статусы проверки и решения по регистрациям может менять только модератор. Поэтому при публикации объявите правила доступа (`admin` — пользователи с правом «Может редактировать», они и есть модераторы):

```json
{"user": {}, "sample": {}, "db": {"rules": [
  {"path": "registrations", "read": "admin", "write": "admin"},
  {"path": "registrations/{self}", "write": "interact"},
  {"path": "moderation", "read": "admin", "write": "admin"},
  {"path": "moderation/{self}", "read": "interact", "write": "admin"},
  {"path": "reps", "write": "admin"},
  {"path": "overrides", "write": "admin"},
  {"path": "decisions", "write": "admin"},
  {"path": "product_edits", "write": "admin"},
  {"path": "product_edits/{self}", "write": "interact"},
  {"path": "sourceflags", "write": "admin"}
]}}
```

Пользователь видит только свою регистрацию и решение по ней, модератор — все. Решения по предложениям и заявкам (`decisions`) видны всем, а записывать их может только модератор. Правки продукции (`product_edits`) каждый пишет только в свой документ; на сайте применяются лишь правки подтверждённого представителя той компании, чья это продукция. Отметки подтверждённых представителей (`reps`, без персональных данных) видны всем, чтобы у их предложений была пометка «Представитель компании подтверждён». Копии уведомлений в Telegram и ВКонтакте отправляет сервер API (`backend/`); опубликованная страница без него показывает уведомления только на сайте.

`tools/seed_*.py` пересобирают `data/` с нуля и отказываются запускаться, если в базе есть компании из синхронизации с реестрами. `--force` удалит их, после этого нужен `python -m sync`.

## Данные (24.09.2026)

12 предприятий (11 — Волгоградская область, 1 — Орловская, как альтернатива для сравнения), 57 позиций продукции и услуг, 26 источников.
Реквизиты и основной ОКВЭД — из сведений ЕГРЮЛ (агрегатор 1cont.ru), продукция — с официальных сайтов.
ОКПД2 предприятия не публикуют: коды классов присвоены по классификатору и помечены `INFERRED`.
Цены, объёмы, сроки, складские остатки не опубликованы ни одним предприятием — в базе их нет.
Статусы: VERIFIED — официальный сайт + реестр без расхождений; PARTIALLY_VERIFIED — есть расхождения или сайт не прочитан; UNVERIFIED — нет реквизитов (ВЗМК); OUTDATED — юрлицо ликвидировано (ВЗБТ).
