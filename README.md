# Промышленная кооперация — MVP

**Команда**: DigitalRevision <br>
**Код команды**: T008 <br>
**Кейсодержатель**: Союз машиностроителей <br>
**Код темы**: SM01 <br>

Цифровая система промышленной кооперации в визуальном языке портала soyuzmash.ru. Пилотный регион — Волгоградская область.

**Принцип:** реальные данные → проверенные источники → поиск → сопоставление → производственная цепочка → поставщик → заявка → кооперация.
Неизвестное хранится как `null` и показывается как «Нет открытых данных», «Не указано», «Цена по запросу» или «Требует подтверждения».

## Состав

| Каталог | Что внутри |
|---|---|
| `pkdb/` | Доступ к базам PostgreSQL: у каждого раздела своя база (`sm01_catalog`, `sm01_ingest`, `sm01_accounts`, `sm01_market`, `sm01_chains`, `sm01_moderation`), схемы `schema/*.sql`, миграции, роли сервисов, начальный набор каталога `seed/`. Подробно: [docs/DATABASE.md](docs/DATABASE.md) |
| `site/` | Фронтенд: `src/` (CSS и JS по модулям), `dist/index.html` после сборки. Каталог сайт получает с сервера (`/api/v1/bundle`), пользовательские данные сохраняет на сервер |
| `backend/` | FastAPI: каталог, поиск с объяснением, заявки, предложения, цепочки, замена поставщика, регистрация и модерация, сессии, права доступа, админ-API; `tests/` |
| `crawler/` | Scrapy: организация → поиск официального сайта (домены по названию и почте, подтверждение ИНН, ОГРН или названием с адресом из ЕГРЮЛ) → обход сайта (robots.txt, пауза между запросами) → страницы и найденные сайты в базу `sm01_ingest`. В карточки их переносит ежедневный сбор (`sync/sitecrawl.py`) или `tools/crawl_products.py auto` |
| `sync/` | Ежедневная синхронизация с реестрами ФНС и Федресурсом: поиск новых промышленных компаний региона и соседних областей, статус и метка закрытия, риски, отчётность, коды ОКВЭД. Подробно: [docs/SYNC.md](docs/SYNC.md) |
| `tools/` | `crawl_products.py` — позиции продукции с официальных сайтов: кандидаты на проверку и запись одобренных; `json_to_pg.py` — перенос прежней JSON-базы в PostgreSQL с проверкой; `validate_data.py` — проверка каталога; `build_site.py` — сборка сайта; `export_bundle.py` — каталог в файл для просмотра без сервера; `seed_*.py` — исторические скрипты первичного сбора |

## Запуск

> [!WARNING]
> Прототип сайта работает исправно, все функции представленные в прототипе имеют форму макета, представлена защита от вариативных атак на сайт.

Установка на сервер (Ubuntu, Docker, домен и HTTPS, резервные копии, обновление): [docs/INSTALL.md](docs/INSTALL.md). На компьютере с Windows без Docker: `start-local.cmd`, сайт откроется на http://localhost:8765.

Кеш и служебные файлы собираются в папке `Trash/`: скачанные открытые данные (`opendata`), кеш страниц краулера (`scrapy`), байт-код Python (`pycache`, при запуске через `start-local.cmd`), кеш pytest, журналы, профили браузера сквозной проверки. Её не нужно копировать на сервер и можно удалить целиком; `clean.cmd` (`python tools/clean.py`) удаляет её вместе с `__pycache__`, которые тесты и редактор оставляют рядом с исходниками. Данные платформы хранятся в PostgreSQL, очистка их не затрагивает.

```bash
export PK_PG_URL=postgresql://postgres:пароль@127.0.0.1:5432/postgres   # сервер PostgreSQL
python -m pkdb.migrate --seed          # базы разделов, схемы, начальный набор каталога
python tools/json_to_pg.py             # (однократно) перенос прежней базы из data/
python tools/validate_data.py          # проверка данных каталога
python tools/build_site.py             # site/dist/
cd backend && pip install -r requirements.txt && python -m pytest -q && uvicorn app.main:app --reload
python -m pytest sync/tests -q         # тесты сбора (свои базы sm01test_*, встроенный PostgreSQL — пакет pgserver)
docker compose up                      # db (PostgreSQL) + migrate + redis + api + sync + crawler + web
docker compose run --rm crawler scrapy crawl company_sites                  # разовый поиск и обход сайтов (сам — после каждого сбора)
python tools/crawl_products.py auto                                         # найденные сайты и позиции — в карточки сразу
python tools/crawl_products.py review --out review.json                     # кандидаты в позиции продукции
python tools/crawl_products.py apply review.json                            # записать одобренные (decision: accept)
python -m sync                         # сверка с реестрами и поиск новых компаний (каждый день в 00:01: --daemon)
```

Настройки сервера API:
- `PK_TOKENS` — токены доступа, JSON `{"токен": "роль"}` (роли: user, company_admin, moderator, admin). Без переменной работают только локальные `dev-user` и `dev-admin`; в `docker compose` по умолчанию токенов нет, и защищённые методы закрыты.
- `PK_TG_WEBHOOK_SECRET` — секрет вебхука бота Telegram (тот же, что в `setWebhook(secret_token=…)`). Без него вебхук отвечает 503.
- `PK_PG_URL` — сервер PostgreSQL; базы разделов — `PK_DB_PREFIX` + раздел (по умолчанию `sm01_…`) или отдельные адреса `PK_DB_URL_<РАЗДЕЛ>`.

### Данные и права доступа

Сайт, открытый с сервера платформы, при первом заходе получает сессию (`POST /api/v1/session`) и сохраняет заявки, предложения,
отклики, регистрации, решения модератора, профиль и цепочки на сервер — в базы своих разделов. Кто что видит и может менять,
проверяет сервер (таблица прав — [docs/DATABASE.md](docs/DATABASE.md), раздел 4). Данные, которые раньше хранились только
в браузере (`localStorage`), сайт один раз переносит на сервер сам. Модератор входит токеном из `PK_TOKENS` (админ-панель) или
получает роль командой `python -m pkdb.admin set-role <id> moderator`.

### Публикация сайта на claude.ai

Без сервера платформы (страница, опубликованная на claude.ai) сайт берёт каталог из `data.json` (`python tools/export_bundle.py`) и хранит заявки, предложения, регистрации и решения модератора в хранилище приложения (`db`). Регистрации содержат персональные данные, а статусы проверки и решения по регистрациям может менять только модератор. Поэтому при публикации объявите правила доступа (`admin` — пользователи с правом «Может редактировать», они и есть модераторы):

```json
{"user": {}, "sample": {}, "db": {"rules": [
  {"path": "registrations", "read": "admin", "write": "admin"},
  {"path": "registrations/{self}", "write": "interact"},
  {"path": "moderation", "read": "admin", "write": "admin"},
  {"path": "moderation/{self}", "read": "interact", "write": "admin"},
  {"path": "reps", "write": "admin"},
  {"path": "overrides", "write": "admin"},
  {"path": "decisions", "write": "admin"},
  {"path": "product_edits", "write": "admin"},
  {"path": "product_edits/{self}", "write": "interact"},
  {"path": "sourceflags", "write": "admin"}
]}}
```

Пользователь видит только свою регистрацию и решение по ней, модератор — все. Решения по предложениям и заявкам (`decisions`) видны всем, а записывать их может только модератор. Правки продукции (`product_edits`) каждый пишет только в свой документ; на сайте применяются лишь правки подтверждённого представителя той компании, чья это продукция. Отметки подтверждённых представителей (`reps`, без персональных данных) видны всем, чтобы у их предложений была пометка «Представитель компании подтверждён». Копии уведомлений в Telegram и ВКонтакте отправляет сервер API (`backend/`); опубликованная страница без него показывает уведомления только на сайте.

`tools/seed_*.py` — исторические скрипты первичного сбора 24.09.2026: пишут JSON в `data/` (в Git не хранится); загрузить результат в базу — `python tools/json_to_pg.py --replace`. Начальный набор для новой установки уже в `pkdb/seed/`.
