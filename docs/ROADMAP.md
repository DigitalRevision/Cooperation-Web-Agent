# План развития платформы «Промышленная кооперация»

**Период:** с октября 2026 по сентябрь 2027 года
**Текущая версия:** 1.2 (пилот, Волгоградская область)
**Репозиторий:** github.com/DigitalRevision/Cooperation-Web-Agent

---

## 1. Кратко

«Промышленная кооперация» помогает предприятию найти проверенного поставщика или партнёра по производству и понять, почему система его предложила.

Пользователь описывает задачу своими словами, например «нужна трубная заготовка из стали 40Х, 500 тонн в месяц». Платформа разбирает запрос на параметры (продукция, материал, объём, регион, коды ОКПД2 и ОКВЭД), подбирает предприятия и по каждому показывает:

- какие критерии совпали и на каком источнике это основано;
- реквизиты из ЕГРЮЛ;
- потенциальные риски и важные факты.

**Главный принцип:** в платформе только проверяемые данные. У каждого значения есть источник и дата проверки. То, что неизвестно, так и отмечено, догадки как факт не показываются.

**Цель на 12 месяцев:** перейти от пилота к рабочему сервису для членов Союза машиностроителей России в 8 регионах, с проверкой контрагентов и сделками внутри платформы.

## 2. Что уже сделано (версии 1.0-1.2)

| Направление | Результат |
|---|---|
| База данных | 12 предприятий, 57 позиций продукции и услуг, 26 источников. У каждого поля есть источник и статус проверки. |
| Поиск поставщика | Разбор запроса на естественном языке, объяснимое сопоставление по 7 критериям, фильтры и сортировка. |
| Карточка предприятия | Реквизиты в формате выписки ЕГРЮЛ, контакты, продукция с кодами ОКПД2, технологии и мощности. |
| Риски и факты | Автоматические правила: ликвидация, расхождения между источниками, одноимённые юрлица, недоступный сайт, возраст компании, сертификаты. |
| Рынок | Заявки покупателей, предложения поставщиков, производственные цепочки с заменой поставщика. |
| Инфраструктура | API на FastAPI (22 метода), схема PostgreSQL из 44 таблиц, сборщик данных на Scrapy, проверка данных и тесты в CI, запуск через Docker. |
| Интерфейс | Фирменный стиль Союза, адаптивная вёрстка для телефонов и планшетов. |

**Ограничения пилота:**

- Реквизиты сверены через агрегатор выписок ЕГРЮЛ, а не напрямую с ФНС.
- Коды ОКПД2 присвоены по классификатору и ждут подтверждения предприятиями.
- Заявки и предложения хранятся в браузере пользователя, а не на сервере.
- Сведений о судах, долгах и отчётности в базе пока нет.

## 4. Этапы развития

### Этап 1. Промышленный запуск (октябрь-декабрь 2026)

**Цель:** платформа работает на сервере, предприятия заходят в свои кабинеты, данные хранятся надёжно.

| Задача | Метод | Результат |
|---|---|---|
| Серверное хранение | Перенос заявок, предложений, цепочек и профилей в PostgreSQL по готовой схеме. Резервное копирование раз в сутки. | Данные не теряются, доступны с любого устройства. |
| Вход и роли | Вход по e-mail с подтверждением, затем вход через Госуслуги для юрлиц (ЕСИА). Роли: пользователь, администратор компании, модератор, администратор. | Предприятие управляет своей карточкой. |
| Подтверждение прав на карточку | Заявка от сотрудника, проверка ИНН и домена почты, подтверждение модератором Союза. | Данные можно менять только подтверждённым представителям. |
| Прямая сверка реквизитов | Выписки ЕГРЮЛ с сайта ФНС (egrul.nalog.ru) и открытые наборы данных ФНС вместо агрегатора. | Реквизиты из первоисточника. |
| Расширение базы по региону | Сбор из ГИСП Минпромторга, реестра российской промышленной продукции (ПП РФ № 719), региональных каталогов. Ручная проверка сайтов, которые не прочитал сборщик. | 150 предприятий Волгоградской области. |
| Подтверждение ОКПД2 | Предприятие подтверждает коды своей продукции в кабинете. | Статус «Присвоено» меняется на «Подтверждено». |
| Хостинг и безопасность | Российский хостинг, HTTPS, соответствие 152-ФЗ (персональные данные хранятся в РФ, есть согласия и политика обработки), журнал действий. | Можно работать с реальными пользователями. |

### Этап 2. Проверка контрагентов (январь-март 2027)

**Цель:** перед сделкой пользователь видит полную картину надёжности поставщика в одной карточке.

| Источник | Что добавляем | Как используем |
|---|---|---|
| ФНС, открытые данные | Среднесписочная численность, налоговый режим, задолженности по налогам, признак недостоверности адреса или руководителя. | Новые риски и факты в карточке. |
| ГИР БО (бухгалтерская отчётность) | Выручка, прибыль, активы за 3 года. | Динамика и финансовые факты. |
| Картотека арбитражных дел | Суды, где компания ответчик, суммы исков. | Риск «судебная нагрузка». |
| ФССП | Исполнительные производства. | Риск «долги по исполнительным листам». |
| ЕИС закупок (44-ФЗ, 223-ФЗ) | Исполненные контракты, заказчики, суммы. | Факт «опыт поставок по госконтрактам». |
| Реестр недобросовестных поставщиков | Наличие в реестре. | Критичный риск. |
| Реестр российской продукции | Продукция в реестре. | Факт для импортозамещения. |

**Метод оценки:** прозрачные правила, а не «чёрный ящик». Каждый риск объясняется одной фразой и ведёт на источник. Итоговый уровень («Критично», «Внимание», «К сведению», «Рисков не выявлено») выводится по самому серьёзному риску. Балльный рейтинг надёжности не вводим, чтобы не давать оценку, которую нельзя объяснить.

**Обновление:** реквизиты раз в неделю, суды и исполнительные производства раз в сутки для предприятий из избранного и из активных сделок. При появлении нового риска пользователь получает уведомление.

### Этап 3. Умный подбор (апрель-июнь 2027)

**Цель:** находить поставщиков, даже если запрос сформулирован не так, как в каталоге предприятия.

| Задача | Метод |
|---|---|
| Смысловой поиск | Векторные представления описаний продукции в PostgreSQL (pgvector) плюс текущие правила. Гибридное ранжирование: правила дают объяснение, векторы находят близкие формулировки. |
| AI-разбор запроса | Языковая модель (Claude) переводит свободный текст в структурированный запрос. Модель только разбирает запрос и никогда не добавляет фактов о предприятиях. |
| Аналоги и импортозамещение | Подбор по коду ОКПД2, материалу и технологии. Отметка продукции из реестра российской продукции. |
| Замена поставщика в цепочке | Если у поставщика появился риск, система предлагает альтернативы с объяснением. |
| Подтверждение мощностей | Предприятие указывает свободные мощности и сроки. Эти данные помечаются как «указано предприятием». |
| Качество поиска | Контрольный набор из 200 реальных запросов, замер точности перед каждым выпуском. |

### Этап 4. Масштабирование и сделки (июль-сентябрь 2027)

**Цель:** 8 регионов, сделки внутри платформы, аналитика для Союза.

| Задача | Метод |
|---|---|
| Новые регионы | Ростовская, Астраханская, Саратовская, Воронежская, Самарская области, Москва и Московская область, Санкт-Петербург и Ленинградская область. Для каждого региона используется тот же конвейер: сбор, сверка с ЕГРЮЛ, проверка модератором. |
| Переписка и коммерческие предложения | Сообщения между покупателем и поставщиком, запрос КП по шаблону, сравнение предложений. |
| Интеграции | Выгрузка заявок и КП в 1С, обмен документами через операторов ЭДО. |
| Уведомления | E-mail и Telegram: новые заявки по профилю предприятия, отклики, изменения рисков. |
| Мобильная версия | Устанавливаемое веб-приложение (PWA) с офлайн-доступом к избранному. |
| Аналитика для Союза | Карта кооперационных связей, дефицитные позиции (частые запросы без поставщика), загрузка мощностей по регионам и отраслям. |

## 5. Методы и технологии

### Сбор данных
- **Источники по приоритету:** официальный сайт предприятия, ЕГРЮЛ и ФНС, ГИСП, отраслевые и региональные каталоги.
- **Сборщик на Scrapy:** соблюдает robots.txt, ограничивает частоту запросов, повторяет запросы при ошибках, ведёт журнал обхода. Сайты на JavaScript читаются через Playwright.
- **Хранение как в Git:** каждое изменение данных попадает в историю, его можно проверить и откатить. Перед публикацией данные проходят автоматическую проверку в CI.

### Проверка данных
- **Статусы:** «Подтверждено» (сайт и реестр совпадают), «Частично подтверждено» (есть расхождения), «Не подтверждено» (нет реквизитов), «Устарело» (юрлицо ликвидировано).
- **Расхождения между источниками** не исправляются автоматически, а показываются пользователю с обоими значениями и источниками.
- **Модерация:** модератор Союза подтверждает права представителей и спорные изменения.

### Поиск и подбор
- Разбор запроса на параметры: правила предметной области, а на этапе 3 также AI.
- Сопоставление по 7 критериям: продукция, ОКПД2, ОКВЭД, материал, технология, география, мощность.
- Каждый результат объясняется: что совпало, что не подтверждено, на каком источнике основано.

### Архитектура
- **Интерфейс:** веб-приложение без тяжёлых фреймворков, быстрое на слабых компьютерах и телефонах.
- **Сервер:** Python, FastAPI, PostgreSQL с расширением pgvector, Redis для кэша и очередей.
- **Развёртывание:** Docker, автоматическая сборка и тесты при каждом изменении.
- **Безопасность:** роли и права доступа, ограничение частоты запросов, журнал аудита, HTTPS, хранение персональных данных в РФ по 152-ФЗ.

### Процесс разработки
- Выпуски раз в 2-4 недели с номером версии и описанием изменений на GitHub.
- Каждое изменение проходит автоматические тесты и проверку данных.
- Демонстрация Союзу в конце каждого этапа.

## 7. Риски проекта и меры

| Риск | Мера |
|---|---|
| Предприятия не заполняют кабинеты | Карточка уже заполнена из открытых источников, представителю нужно только подтвердить данные. Первыми подключаем пилотные предприятия Союза. |
| Данные устаревают | Автоматическое обновление по расписанию, дата проверки у каждого значения, уведомление представителю при расхождении. |
| Ограничения доступа к источникам | Используем официальные открытые данные и API. Коммерческие агрегаторы только как резерв и с пометкой. |
| Ошибки AI при разборе запроса | AI только разбирает запрос, факты о предприятиях берутся из базы. Пользователь видит, что распознано, и может это исправить. |
| Требования к персональным данным | Хранение в РФ, согласия, политика обработки, минимум персональных данных в карточках. |

## 8. Что нужно для старта
