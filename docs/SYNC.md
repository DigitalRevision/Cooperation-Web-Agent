# Ежедневная синхронизация с реестрами

Пакет `sync/` раз в сутки обходит промышленные компании Волгоградской области и соседних регионов (Астраханская, Ростовская, Саратовская, Воронежская области, Республика Калмыкия), сверяет их с базой и обновляет сайт.

## Что делает один проход

1. **Поиск компаний.** ГИР БО ФНС по классам ОКВЭД 10–33 (раздел C «Обрабатывающие производства») в каждом регионе: около 250 запросов, 4–5 минут.
2. **Новые компании.** Добавляются, если юрлицо действует, выручка за последний год не ниже порога (по умолчанию 10 млн ₽), и не больше 300 за запуск, самые крупные первыми. Реквизиты подтверждаются ЕГРЮЛ, статус `PARTIALLY_VERIFIED`, поле `origin: "registry_sync"`.
3. **Проверка каждой компании базы:**
   - каждый день: ЕГРЮЛ (статус, реквизиты, дата прекращения) и Федресурс (банкротство, намерения кредиторов);
   - раз в неделю, для новых и при смене статуса: «Прозрачный бизнес» ФНС, отчётность ГИР БО, Checko (если задан ключ);
   - раз в месяц: открытые данные ФНС (скачиваются, только когда ФНС опубликовала новый файл).
4. **Слияние и запись:** `data/companies/*`, справочники ОКВЭД и регионов, журнал `data/sync/<дата>_<время>.json` и `latest.json`, бандл `site/data.json` (и `site/dist/data.json`, если сайт собран). API перечитывает данные сам, когда меняется `latest.json`.

## Источники

| Источник | Что даёт | Доступ |
|---|---|---|
| ГИР БО ФНС, bo.nalog.gov.ru | поиск по ОКВЭД и региону, выручка, прибыль, активы, капитал, ОКПО | открыто, JSON |
| ЕГРЮЛ ФНС, egrul.nalog.ru | статус, реквизиты, дата ликвидации | открыто; 48 компаний подряд без капчи при паузе 1,5 с |
| Федресурс и ЕФРСБ, fedresurs.ru | дела о банкротстве и их стадия, намерения кредиторов | открыто, JSON |
| Открытые данные ФНС, nalog.gov.ru/opendata | недоимка, пени и штрафы; численность; уплаченные налоги; налоговый режим | открыто, архивы 60–220 МБ, раз в месяц |
| «Прозрачный бизнес» ФНС, pb.nalog.ru | недостоверность сведений, непредставление отчётности, массовый адрес и руководитель, все коды ОКВЭД, адрес, капитал, категория МСП | открыто, но капча уже после нескольких карточек: 40 карточек за запуск с паузой 8 с, при капче источник откладывается до следующего дня |
| Checko API, api.checko.ru | арбитражные дела (ответчик), исполнительные производства ФССП, реестр недобросовестных поставщиков, санкции | платно, ключ `PK_CHECKO_KEY`; без ключа не вызывается |

ГИСП (gisp.gov.ru) закрыт защитой от ботов (HTTP 403), поэтому производственные возможности берутся из кодов ОКВЭД ЕГРЮЛ (`capabilities_declared`). На сайте они показаны как заявленные, а в подборе дают оценку «совместимо», а не «подтверждено».

## Статус и метка закрытия

`status_code`: `ACTIVE`, `REORGANIZING`, `LIQUIDATING`, `BANKRUPTCY`, `LIQUIDATED`. Текст для людей хранится в `legal_status` («Банкротство: конкурсное производство с 10.10.2025, дело А12-5342/2025», «Ликвидировано 15.10.2024»). Ликвидированная компания получает `verification_status: OUTDATED` и исчезает из подбора. Статус понижается (например, «банкротство» → «действующее») только если ответили все источники, на которых он держался. Если текст статуса заведён вручную и код не изменился, текст не переписывается.

## Риски (`risk_signals`)

| Код | Уровень | Правило |
|---|---|---|
| INVALID_DATA | high | ФНС отметила сведения ЕГРЮЛ как недостоверные |
| NO_REPORTS | high | не сдаёт налоговую отчётность больше года |
| TAX_ARREARS | high от 1 млн ₽, иначе mid | недоимка, пени и штрафы по открытым данным ФНС |
| NEGATIVE_EQUITY | high | капитал и резервы (строка 1300) меньше нуля |
| UNFAIR_SUPPLIER | high | в реестре недобросовестных поставщиков (Checko) |
| ENFORCEMENTS | high от 1 млн ₽, иначе mid | исполнительные производства ФССП (Checko) |
| BANKRUPTCY_INTENT | mid | за год были сообщения о намерении подать на банкротство |
| LOSS | mid | чистый убыток за последний год |
| REVENUE_DROP | mid | выручка упала больше чем вдвое |
| MASS_ADDRESS, MASS_HEAD | mid | массовый адрес (10 и больше юрлиц) или руководитель |
| COURTS_DEFENDANT, SANCTIONS, DISQUALIFIED | mid или low | по данным Checko |
| NO_FINANCIALS, VESTNIK | low | нет свежей отчётности; сообщения в «Вестнике государственной регистрации» |

Сигнал от источника, который в этом запуске не ответил, сохраняется с прошлого раза. Изменения попадают в `history` компании (последние 30) и в журнал запуска; на сайте они видны в разделе «История изменений», а новые риски у избранных компаний приходят в уведомления.

## Запуск

```bash
pip install httpx
python -m sync                          # полный проход
python -m sync --dry-run --limit 5      # проверка без записи
python -m sync --no-discover            # только компании базы
python -m sync --regions 34 --okved 25,28 --max-new 20
python -m sync --daemon --at 03:00      # постоянно, запуск каждый день в 03:00
python -m pytest sync/tests -q          # тесты без сети
```

Docker: сервис `sync` в `docker-compose.yml` запускается вместе с остальными и работает в режиме `--daemon`.

Windows без Docker (Планировщик заданий):

```
schtasks /Create /SC DAILY /ST 03:00 /TN "PromKoop sync" /TR "cmd /c cd /d C:\путь\к\проекту && python -m sync >> data\sync\run.log 2>&1"
```

Сайты ФНС могут не открываться с зарубежных IP, поэтому запускайте синхронизацию на сервере в России (GitHub Actions для этого не подходит).

## Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PK_SYNC_MIN_REVENUE_K` | 10000 | порог выручки новой компании, тыс. ₽; 0 — все действующие |
| `PK_SYNC_MAX_NEW` | 300 | новых компаний за запуск |
| `PK_SYNC_PB_PER_RUN` | 40 | карточек «Прозрачного бизнеса» за запуск |
| `PK_SYNC_PB_DELAY` | 8 | пауза между запросами к pb.nalog.ru, с |
| `PK_SYNC_DELAY` | 1.0 | пауза между запросами к остальным сайтам, с |
| `PK_CHECKO_KEY` | нет | ключ Checko API |
| `PK_DATA_DIR` | data/ | каталог данных |

На 24.09.2026 в шести регионах 15 267 организаций с основным ОКВЭД раздела C, из них 12 215 действующих; с выручкой от 10 млн ₽ — 6 138. При лимите 300 в день первый полный обход займёт около трёх недель.
