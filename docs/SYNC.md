# Ежедневная синхронизация с реестрами

Пакет `sync/` раз в сутки обходит промышленные компании Волгоградской области и соседних регионов (Астраханская, Ростовская, Саратовская, Воронежская области, Республика Калмыкия), сверяет их с базой и обновляет сайт.

## Что делает один проход

1. **Поиск компаний.** ГИР БО ФНС по классам ОКВЭД машиностроения и работы с металлом и компонентами: 24 металлургия, 25 металлоизделия, 26 электронные компоненты, 27 электрооборудование, 28 машины и оборудование, 29–30 транспортное машиностроение, 33 ремонт и монтаж оборудования. Пищевая, лёгкая, химическая и прочая промышленность не собирается. Другой набор классов — переменная `PK_SYNC_OKVED` или ключ `--okved`.
2. **Новые компании.** Добавляются все действующие компании любого размера, но не «пустые»: выручка за последний год больше нуля (порог `PK_SYNC_MIN_REVENUE_K`, по умолчанию 1 тыс. ₽). Не больше 5000 за запуск, самые крупные первыми. Реквизиты подтверждаются ЕГРЮЛ, статус `PARTIALLY_VERIFIED`, поле `origin: "registry_sync"`.
3. **Проверка каждой компании базы:**
   - каждый день: ЕГРЮЛ (статус, реквизиты, дата прекращения) и Федресурс (банкротство, намерения кредиторов);
   - раз в неделю, для новых и при смене статуса: «Прозрачный бизнес» ФНС, отчётность ГИР БО, Checko (если задан ключ);
   - раз в месяц: открытые данные ФНС (скачиваются, только когда ФНС опубликовала новый файл).
4. **Слияние и запись в PostgreSQL:** изменённые карточки и справочники ОКВЭД и регионов — одной транзакцией в базу `sm01_catalog`, ревизия каталога растёт; журнал прохода (сводка, изменения, ошибки источников) — в `sm01_ingest` (`sync_run`, `sync_change`, `sync_error`). API замечает новую ревизию в течение 5 секунд и перечитывает каталог. Файлов и коммитов в Git сбор не создаёт ([docs/DATABASE.md](DATABASE.md)).

ГИСП (gisp.gov.ru) закрыт защитой от ботов (HTTP 403), поэтому производственные возможности берутся из кодов ОКВЭД ЕГРЮЛ (`capabilities_declared`). На сайте они показаны как заявленные, а в подборе дают оценку «совместимо», а не «подтверждено».

## Продукция из реестра промышленной продукции Минпромторга

Реестр российской промышленной продукции (постановление Правительства РФ № 719) — продукция, производство которой в России
подтверждено актом экспертизы ТПП или заключением Минпромторга. Это тот же реестр, что на gisp.gov.ru, но опубликованный
открытыми данными (набор `1000000012-ReestrProducts`). На 25.09.2026 в нём 516 773 записи 8091 производителя; из 4536
предприятий базы в реестре 175, у них 12 474 действующие позиции.

Файл скачивается в `sync/.cache/opendata/minpromtorg` не чаще раза в `PK_SYNC_MPT_DAYS` дней (по умолчанию 7); обрыв — докачка
с места обрыва, размер сверяется с заголовком сервера. Из файла берутся записи по ИНН предприятий базы, только действующие:
не исключённые из реестра и со сроком действия не раньше сегодняшнего дня. Если запись продлевали, остаётся последняя.

Позиции записываются с id `<id предприятия>-rpp-<реестровый номер>` и источником `<id>-minprom` (тип `MPT_REESTR`, приоритет 4):
наименование — дословно из реестра, код ОКПД2 со статусом `SOURCE`, характеристики — ТН ВЭД, ТУ или ГОСТ, реестровая запись,
баллы или доля локализации; в описании — документ, подтвердивший производство, и срок действия записи. При следующей загрузке
заменяются только позиции этого источника, продукция из других источников не трогается. Филиалы, заведённые с ИНН головной
компании, позиции не получают: записи по этому ИНН относятся ко всем заводам компании.

Включён по умолчанию; `--no-minprom` (или `--no-opendata`) — пропустить.

## Сайты и продукция, найденные краулером

Краулер (`crawler/`, docs/INSTALL.md) ищет официальные сайты предприятий и обходит их, но карточки не меняет. Ежедневный сбор
переносит в карточки то, что краулер подтвердил (`sync/sitecrawl.py`): сайт, найденный по ИНН, ОГРН или названию с адресом
из ЕГРЮЛ, — в поле «Сайт» и источник «Официальный сайт»; позиции со страниц каталога сайта — в продукцию с источником
`<id>-web-<хеш адреса страницы>`, если у позиции есть признак товара (характеристики на странице, марка или модель в названии,
ещё одна позиция той же линейки; `auto_accept`), остальные ждут модератора; известным позициям, найденным на сайте, — новую
дату проверки. Разбираются только предприятия
со страницами обхода новее прошлого разбора (отметка `crawl_applied_at` в состоянии сбора). Ключ `--no-crawl` — пропустить.
То же вручную, не дожидаясь сбора: `python tools/crawl_products.py auto`.

## Продукция из реестра МСП (по ключу)

Единый реестр субъектов МСП ФНС (открытые данные, набор `rsmp`) содержит сведения о производимой продукции, которые предприятие
указывает само: код ОКПД2 и наименование. Это официальный источник по ИНН, но заполняют его редко: на 10.09.2026 во всём реестре
10 449 таких записей на 6,77 млн субъектов (0,15 %), из 4532 предприятий базы — у трёх. Архив весит около 2 ГБ и обновляется
раз в месяц, поэтому в ежедневном сборе он включается явно: ключ `--rmsp` или `PK_SYNC_RMSP=1`.

Позиции из реестра записываются с источником `<id>-rmsp` (тип `FNS_RMSP`) и кодом ОКПД2 со статусом `SOURCE`; при следующей
загрузке заменяются только они, продукция из других источников не трогается. Если предприятие убрало продукцию из реестра,
позиции этого источника снимаются. Архив проверяется после загрузки: file.nalog.ru иногда отдаёт испорченный поток без обрыва
соединения, повреждённые участки перекачиваются по HTTP Range.

Тем же проходом по архиву собираются названия кодов ОКПД2 из всех документов реестра (предприятие выбирает код из
классификатора, реестр хранит его название): ими заполняется справочник `okpd2` там, где названия нет. У подробных кодов реестра
Минпромторга названий в открытых данных нет; сайт показывает название ближайшей группировки. На 10.09.2026 — 1661 название.

## Статус и метка закрытия

`status_code`: `ACTIVE`, `REORGANIZING`, `LIQUIDATING`, `BANKRUPTCY`, `LIQUIDATED`. Текст для людей хранится в `legal_status` («Банкротство: конкурсное производство с 10.10.2025, дело А12-5342/2025», «Ликвидировано 15.10.2024»). Ликвидированная компания получает `verification_status: OUTDATED` и исчезает из подбора. Статус понижается (например, «банкротство» → «действующее») только если ответили все источники, на которых он держался. Если текст статуса заведён вручную и код не изменился, текст не переписывается.

## Риски (`risk_signals`)

| Код | Уровень | Правило |
|---|---|---|
| INVALID_DATA | high | ФНС отметила сведения ЕГРЮЛ как недостоверные |
| NO_REPORTS | high | не сдаёт налоговую отчётность больше года |
| TAX_ARREARS | high от 1 млн ₽, иначе mid | недоимка, пени и штрафы по открытым данным ФНС |
| NEGATIVE_EQUITY | high | капитал и резервы (строка 1300) меньше нуля |
| UNFAIR_SUPPLIER | high | в реестре недобросовестных поставщиков (Checko) |
| ENFORCEMENTS | high от 1 млн ₽, иначе mid | исполнительные производства ФССП (Checko) |
| BANKRUPTCY_INTENT | mid | за год были сообщения о намерении подать на банкротство |
| LOSS | mid | чистый убыток за последний год |
| REVENUE_DROP | mid | выручка упала больше чем вдвое |
| MASS_ADDRESS, MASS_HEAD | mid | массовый адрес (10 и больше юрлиц) или руководитель |
| COURTS_DEFENDANT, SANCTIONS, DISQUALIFIED | mid или low | по данным Checko |
| NO_FINANCIALS, VESTNIK | low | нет свежей отчётности; сообщения в «Вестнике государственной регистрации» |

Сигнал от источника, который в этом запуске не ответил, сохраняется с прошлого раза. Изменения попадают в `history` компании (последние 30) и в журнал запуска; на сайте они видны в разделе «История изменений», а новые риски у избранных компаний приходят в уведомления.

## Запуск

```bash
pip install httpx
python -m sync                          # полный проход
python -m sync --dry-run --limit 5      # проверка без записи
python -m sync --no-discover            # только компании базы
python -m sync --regions 34 --okved 25,28 --max-new 20
python -m sync --daemon                 # постоянно: каждый день в 00:01 и по кнопке в админ-панели
python -m pytest sync/tests -q          # тесты без сети (свои базы sm01test_*)
```

**Ручной запуск.** В админ-панели, вкладка «Сбор данных»: кнопка «Запустить сбор сейчас», ход сбора (этап, сколько компаний проверено) и итоги последнего запуска. Кнопка обращается к API платформы (`POST /api/v1/admin/sync/run`, роль admin). Если работает планировщик, API оставляет ему запрос в таблице `sync_request` базы `sm01_ingest`, и сбор начинается в течение 15 секунд; если планировщик не запущен, API запускает `python -m sync` сам. Два сбора одновременно не идут: пока идёт один, блокировка `sync_lock` (обновляется раз в минуту) не даёт начать второй; блокировку, которую не обновляли 10 минут, занимает следующий запуск. Этап, прогресс и итоги последнего запуска — в `sync_state`. Кнопка работает, когда сайт открыт с сервера платформы (`docker compose up`, затем http://localhost:8080: nginx передаёт `/api` серверу API).

Docker: сервис `sync` в `docker-compose.yml` запускается вместе с остальными и работает в режиме `--daemon`.

Windows без Docker (Планировщик заданий):

```
schtasks /Create /SC DAILY /ST 00:01 /TN "PromKoop sync" /TR "cmd /c cd /d C:\путь\к\проекту && set PK_PG_URL=postgresql://… && python -m sync >> sync\run.log 2>&1"
```

Сайты ФНС могут не открываться с зарубежных IP, поэтому запускайте синхронизацию на сервере в России (GitHub Actions для этого не подходит).

## Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PK_SYNC_OKVED` | 24,25,26,27,28,29,30,33 | классы ОКВЭД, по которым ищутся компании |
| `PK_SYNC_MIN_REVENUE_K` | 1 | порог выручки новой компании, тыс. ₽; не меньше 1: компании без выручки не добавляются никогда |
| `PK_SYNC_AT` | 00:01 | время ежедневного запуска планировщика |
| `PK_SYNC_MAX_NEW` | 5000 | новых компаний за запуск |
| `PK_SYNC_PB_PER_RUN` | 40 | карточек «Прозрачного бизнеса» за запуск |
| `PK_SYNC_PB_DELAY` | 8 | пауза между запросами к pb.nalog.ru, с |
| `PK_SYNC_DELAY` | 1.0 | пауза между запросами к остальным сайтам, с |
| `PK_CHECKO_KEY` | нет | ключ Checko API |
| `PK_SYNC_RMSP` | нет | `1` — загружать продукцию и названия кодов ОКПД2 из реестра МСП (архив около 2 ГБ раз в месяц) |
| `PK_SYNC_MPT_DAYS` | 7 | как часто скачивать заново реестр промышленной продукции Минпромторга (файл около 420 МБ), дней |
| `PK_PG_URL` | postgresql://postgres@127.0.0.1:5432/postgres | сервер PostgreSQL; сбор пишет в базы `sm01_catalog` и `sm01_ingest` (отдельные адреса — `PK_DB_URL_CATALOG`, `PK_DB_URL_INGEST`) |

На 24.09.2026 в шести регионах 15 267 организаций с основным ОКВЭД раздела C (классы 10–33), из них 12 215 действующих. С 25.09.2026 парсер собирает только машиностроение и работу с металлом (классы 24–30 и 33), все действующие компании с выручкой больше нуля.
